## Q1. NSTimer 导致的循环引用

泄漏排查建议“先定类目再定位”：持续增长对象（业务缓存）、生命周期泄漏（闭包/Timer/通知）、系统资源泄漏（CG/CF）。野指针通常来自越界访问或 `unsafe_unretained`。循环引用最常见是 `self -> block -> self`、`NSTimer/CADisplayLink`、和 delegate 误用 strong。策略是建立销毁点（deinit/dealloc 日志）和弱引用断环，并配自动化回归检测。

**面试加分回答框架：**
1. 先给结论与适用边界。
2. 说明底层机制或关键原理。
3. 给出真实项目中的坑与治理方案。
4. 补充如何验证（指标 / 工具 / 回归方式）。

final class SSProfileViewController: UIViewController {
