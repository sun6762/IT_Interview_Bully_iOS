## Q1. 内联（最快）

这类问题建议按“原理 -> 典型坑 -> 工程实践 -> 监控验证”四段回答。资深候选人要给出可落地策略：明确边界、可测试、可观测、可回滚，而不是只停留在 API 记忆层。

**面试加分回答框架：**
1. 先给结论与适用边界。
2. 说明底层机制或关键原理。
3. 给出真实项目中的坑与治理方案。
4. 补充如何验证（指标 / 工具 / 回归方式）。

### 代码示例

```swift
protocol SSQuestionRepository {
    func fetchQuestions() -> AnyPublisher<[String], Error>
}
```

### 追问点

- 如果这个问题在高并发或弱网场景下会放大什么风险？（围绕「内联（最快）」）
- 线上出现同类问题时，你会先看哪三个指标或日志？
- 这个方案在团队协作中如何避免被后续迭代破坏？

### 反问点

- 你们线上与「内联（最快）」相关最常见事故是什么？通常怎么复盘？
- 团队对性能/稳定性是否有明确基线和回归门禁？
- 该模块是否有可观测体系（崩溃、卡顿、内存、耗电）和告警？
